# 我把公司的日志排障经验，做成了一个开源工具

> 一个 Java 后端在电力项目上蹲了三年，最后把那套"人肉 grep"的排障流程，做成了一个能跑起来的开源项目。

## 一、那个凌晨两点

告警响了：无人机巡检平台大量任务超时。

三个微服务、两台服务器、一天几百万条日志。我登录上去做的第一件事，和大多数人一样：

```bash
grep "ERROR" app.log | tail -100
```

翻了四十分钟，才定位到是 Redis 连接被占满，导致缓存全部击穿、请求打到数据库。

事后复盘，真正让我难受的不是故障本身，而是：**有用的信息其实一直就在日志里，只是没人能在几百万行里一眼看出来。**

那次之后我在公司写了个脚本，把巡检日志接进 AI 工具链做分类和根因初判。效果不错，但它长在公司的内网里，换个人就用不了。

于是有了这个项目：**LogPilot**。

## 二、第一反应：把日志直接丢给大模型？

我试过。把 1000 条日志贴进对话框，问"根因是什么"。结果三个问题立刻暴露：

| 问题 | 具体表现 |
|---|---|
| **成本** | 一次几千 token，几分钱到几毛钱；一天几十次告警，一个月是笔真钱 |
| **幻觉** | 模型会编造日志里根本没出现的服务名和错误码 |
| **延迟** | 8–15 秒。告警场景里，这 15 秒比你想象的长 |

结论很直接：**日志不能原样喂给模型，得先压缩。**

问题的本质是：一百万条日志里，可能只有五十种"形状"。人看不出来，因为每条日志的 ID、时间戳、IP 都不一样；机器也看不出来，因为它不知道哪些部分是变量。

## 三、先聚类：把"看日志"变成"看形状"

这就是日志模板提取要解决的问题。业界经典做法是 **Drain**（ICWS 2017），核心思路三步：

1. 按 token 数量分层（不同长度的日志不互相比）
2. 逐 token 比较，相似度超过阈值就合并
3. 把不一致的位置替换成通配符 `<*>`

举个例子：

```
原始：Connection to 10.0.0.11:8080 failed after 3000ms
原始：Connection to 10.0.0.12:8080 failed after 5120ms
模板：Connection to <*> failed after <*>ms
```

我在实现时做了个取舍：**省略论文里的固定深度前缀树，改成同长度桶内线性扫描。**

理由是模板数量在千级以内时，线性扫描完全够用，而代码量能从 500 行降到 100 行——**能让别人读懂，比性能多几个纳秒重要**。

实测效果（仓库里的 `samples/demo.log`）：

```
30 条日志 → 17 个模板
```

真实场景的压缩比通常在 100:1 以上。这一步做完，喂给模型的东西从"一坨文本"变成了"一张统计表"：

```
1. [5 次] order <*> created, userId=<*>, amount=<*>
2. [4 次] Connection to <*> failed after <*>ms
3. [3 次] Slow query detected: select * from t_order where id = <*> took <*>ms
...
```

**模型看到的不再是日志，而是"哪种形状在突增"。** 而"突增"这件事，恰恰是原始日志里看不出来的信号。

## 四、为什么是"规则 + LLM"，而不是纯 LLM

聚类解决了成本问题，但还没解决可靠性问题。我的做法是**规则先行，LLM 增强**：

| | 规则引擎 | LLM |
|---|---|---|
| 已知故障（OOM、连接拒绝、慢 SQL…） | 快、准、零成本、结果稳定 | 没必要，还可能答歪 |
| 未知故障 | 覆盖不到 | 能跨模板推理 |
| 可用性 | 不依赖任何外部服务 | 会超时、会限流、会返回乱码 |

所以执行顺序是刻意的：

```
1. 先跑规则 → 拿到一份"一定能交付"的结论
2. 再调 LLM → 成功则覆盖根因、补充证据与建议
3. LLM 任何异常 → 只让报告标记 degraded，规则结论照样出
```

对应到代码里，接口永远不会因为模型挂了返回 500。这条底线，比多识别一种故障模式重要得多。

## 五、三个降级设计

这是我觉得整个项目里最值得讲的部分——**不是因为做了多少功能，而是因为想清楚了"坏了怎么办"**。

### 1. LLM 不可用时

报告里会有三个字段说明它走了哪条路：

```json
{ "degraded": false, "llmModel": "deepseek-chat", "degradedReason": null }
{ "degraded": true,  "degradedReason": "LLM 调用失败：Connection refused" }
```

页面上的徽章会从「LLM · deepseek-chat」变成「规则模式 · 未配置 api-key」。

**"没配 Key"和"调不通"要分开**——因为这两种情况的排查动作完全不同。

### 2. Redis 不可用时

Redis 在这个项目里承担三件事：日志指纹去重、分析任务锁、LLM 结果缓存。

但它**是增强项，不是依赖**。所有操作走一个 `RedisGuard`，异常全吞 + 30 秒熔断：

```java
// 失败时的返回值约定，直接决定降级行为
markIfAbsent 失败 → 返回 true   // 当作"没见过"，宁可多存也不丢日志
tryLock      失败 → 返回 true   // 当作"拿到锁"，宁可多做一次也不卡用户
```

这两个默认值是反复推敲过的：**去重失效的代价是多写几条数据，丢日志的代价是排障时缺证据。** 两害相权，宁可多存。

### 3. 模型返回不合法 JSON 时

要求模型输出 JSON 容易，保证它真的输出 JSON 很难。所以解析做了两层容错：

```
截取第一个 { 到最后一个 } → 还解析不了，就当这次没有结果
```

不允许"尽力猜"，因为**猜错的根因比没有根因更危险**。

## 六、踩过的坑

几个真实踩出来的，写下来给后来人省点时间：

**1. H2 文件库被强杀后会锁成只读**

开发时用 `Ctrl+C` 或任务管理器杀掉进程，下次启动报 `The database is read only`。原因是文件锁状态没释放干净。

后来默认库换成内存模式，持久化交给 MySQL。**开发环境的首要目标是"永远能干净启动"，不是"数据不能丢"。**

**2. 容器里的 JVM 不知道自己的 limit**

宿主机 32G，容器限制 768M，JVM 默认堆可能按宿主机算到 8G，一跑就被 OOM Kill。

所以 Dockerfile 里必须显式写：

```dockerfile
ENV JAVA_TOOL_OPTIONS="-Xms256m -Xmx512m -Dfile.encoding=UTF-8"
```

**3. 日志指纹不能用 `String.hashCode()`**

它是 32 位，几十万条日志下冲突率不可忽略。而**冲突意味着两条不同的日志被当成重复丢掉**——排障时丢证据是致命的。

换成 SHA-256 取前 128 位，成本可以忽略。

**4. Windows 批处理不要写中文注释**

`.cmd` 文件是 UTF-8，但 `cmd.exe` 按 GBK 解析，中文注释会把整行拆成命令，报 `'避免终端默认' is not recognized`。

**5. Mockito 在受限环境里 attach 失败**

`@SpringBootTest` 启动时报 `JDK does not supply a working agent attachment mechanism`。因为 Mockito 5 默认的 inline mock maker 要动态 attach Java agent。

加一个测试配置切回 subclass 就行：

```
src/test/resources/mockito-extensions/org.mockito.plugins.MockMaker
内容：mock-maker-subclass
```

## 七、我特意"没做"的事

这部分可能比"做了什么"更能说明判断：

| 没做 | 原因 |
|---|---|
| 不用 Elasticsearch | 吃内存，2C2G 的机器起不来；MVP 用 MySQL 聚合足够 |
| 不拆 9 个微服务 | 3 个模块足够讲清架构，多了跑不起来，反而扣分 |
| 不做多副本部署 | 模板状态在 JVM 内存里，多副本会各算各的，统计结果不一致 |
| 不做多租户 | MVP 阶段没有意义 |

最后一条尤其想强调。K8s 里我**固定 1 个副本**，并在文档里写清楚原因：

> 要水平扩展，得先把模板状态外置到 Redis。在此之前不要调大 replicas。
> **宁可部署得保守，也不要一个看起来能扩展、结果却不对的系统。**

一个"能扩容但结果是错的"系统，比"暂时不能扩容"危险十倍。

## 八、现在它是什么样

- Java 17 + Spring Boot 3，Drain 聚类 + 规则引擎 + LLM 归因
- Redis 承担去重/锁/缓存，全部可降级
- Docker 多阶段构建 + Compose 一键起，附 K8s 清单
- 15 个测试（算法单测 + 全链路集成 + 健康检查），CI 全绿
- 没有 API Key 也能完整演示：仓库里带了假的 LLM 和假的 Redis

**代码**：https://github.com/myd31588-create/logpilot

---

做这个项目最大的收获，不是学会了怎么调模型接口，而是想明白了一件事：

**AI 能让一个功能变聪明，但让系统能用的，永远是那些"出错了怎么办"的设计。**

规则兜底、超时降级、熔断、幂等、可观测——这些老掉牙的东西，在 AI 时代一个都没少，反而更重要了。因为你的系统里多了一个**会超时、会胡说、还按 token 收费**的组件。
